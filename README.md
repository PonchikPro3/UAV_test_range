главой: модель деятельности UML, автоматизируемые операции, логическая

## Запуск

Нужны Python 3.9 или новее и JDK 11 или новее. Внешние библиотеки не нужны.
Компилятор `javac` должен быть доступен в системе. При необходимости задайте
переменную `JAVAC` с полным путём к компилятору. Запускающий файл выбирает
`java` из той же установки JDK.

```text
python run_demo.py
```

Скрипт компилирует Java, выполняет проверки и создаёт результаты в `results/`.
Все пути определяются относительно проекта; запуск возможен из другого
рабочего каталога. Повторный запуск обновляет демонстрационные результаты.

## Правила расписания

Интервал полуоткрытый: `[начало, конец)`. Касание концов не создаёт конфликт.
Пересекающиеся интервалы конфликтуют при совпадении зоны или аппарата, а
также при соседних зонах, если хотя бы один сценарий имеет признак
воздействия `interference=true`. В рамках модели этот признак означает
несовместимость; он не моделирует физику распространения воздействия.
Отменённые и завершённые записи пропускаются, собственная запись
исключается по `test_id`. Временные метки обязательно содержат часовой пояс.

`schedule.csv` содержит фиксированные поля:

```text
test_id,zone_id,uav_id,start,end,status,interference
```

В этих полях нет вложенных запятых и кавычек. Допустимые статусы:
`PLANNED`, `APPROVED`, `RUNNING`, `CANCELLED`, `COMPLETED`.
Идентификаторы состоят из латинских букв, цифр, дефиса и подчёркивания.
Проверка готовности требует подтверждения каждого типа документа и срока
действия не ранее конца запрошенного интервала.

Ожидаемый результат исходного запроса: документы готовы, бронирование
невозможно; причины — `T1:SAME_ZONE`, `T2:ADJACENT_INTERFERENCE`,
`T3:SAME_UAV`. Запрос на 12:00–13:00 с соответствующим сроком чек-листа
проходит проверку и сохраняется в `results/planning_free.json`.

## Правила анализа

Фиксированный заголовок CSV:

```text
time_s,x_m,y_m,height_m,speed_m_s,battery_pct
```

Координаты — локальные метры, время — секунды с начала записи. Границы
прямоугольника и числовые пороги включены в допустимую область. Время
строго возрастает. NaN, бесконечность, отрицательные время, высота и скорость,
заряд вне диапазона 0–100, неверные заголовки и поля вызывают ошибку.

Исходный пример даёт пять отсчётов, четыре отклонения, максимальную высоту
121 м, максимальную скорость 16 м/с, минимальный заряд 19 %. Проект
протокола имеет статус `DRAFT` и результат `FAILED`. SHA-256 вычисляется
в том же проходе по байтам, из которых получены анализируемые отсчёты.
Для `OUTSIDE_ZONE` поле `actual_value` содержит расстояние до прямоугольника
в метрах, `limit_value` равно нулю; для остальных кодов — измеренное значение
и соответствующий порог.

Все примеры учебные. Фактические полёты не выполнялись. Решение о
проверке документов и утверждении протокола принимает сотрудник.
Результат относится к дискретным отсчётам; движение между ними не
восстанавливается. СУБД, интерфейсы и транзакционное бронирование относятся
к дальнейшей реализации.

## Отчёт

Отчёт дополнен на основе исходного файла; официальные формы, данные
студента и график сохранены. Применены A4, поля 30/15/20/20 мм,
Times New Roman 14 пт для основного текста, интервал 1,5, абзац 1,25 см,
сквозная нумерация, содержание и подписи рисунков и таблиц. Для таблиц,
подписей и листинга используется компактный одинарный интервал.

Неподтверждённые записи первоначальной библиографии заменены проверяемыми
официальными и техническими источниками; связанные категоричные
утверждения уточнены. Старые стандарты и спецификации используются как
нормативные технические источники, а не как обзор свежих исследований.
Локальная резервная копия отчёта до дополнения сохранена в
`.work/stage3/original.docx`; служебный каталог `.work/` в репозиторий не включён.
